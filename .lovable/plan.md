# يمّك — خطة البناء

**ويّانه كلشي صار يمّك** — منصة عراقية موحدة للخدمات والتوصيل، Mobile-First، عربية RTL بالكامل.

سأبني النواة أولاً (المرحلة الأولى) بشكل حقيقي وقابل للتوسع، وليس واجهات وهمية.

## الأساس التقني
- **Lovable Cloud** كقاعدة بيانات موحدة + مصادقة + منطق خلفي آمن.
- الصلاحيات محسومة في قاعدة البيانات (RLS + جدول أدوار منفصل)، وليس في الواجهة.
- منطق التوزيع وتغيير الحالات والتقييم يعمل على الخلفية.
- تخزين مؤقت للبيانات الثابتة (الخدمات، الأقسام، المطاعم) مع تحديث كل 6 ساعات وعمل بدون إنترنت، والبيانات الحية (حالة الطلب، موقع المندوب) لا تُقرأ من الكاش.

## قاعدة البيانات (المرحلة الأولى)
- **الجغرافيا**: `cities`, `areas`, `service_zones` — قابلة للإدارة بدون كود.
- **المستخدمون**: `profiles`, `user_roles` (enum: super_admin, admin, supervisor, customer, worker, provider)، `worker_profiles` (نوع العمل + حالة الاعتماد)، `providers` (مطعم/متجر/مهنة + حالة المراجعة/الموافقة/كود التفعيل).
- **الخدمات الديناميكية**: `service_sections`, `services` (اسم، وصف، أيقونة، نوع، قسم، مكان الظهور، ترتيب، تفعيل).
- **الكتالوج**: `menu_categories`, `products` (وجبات/منتجات، سعر، صور، كلمات مفتاحية، توفر).
- **الطلبات**: `orders` (حالة موحدة عبر enum يشمل كل الحالات المذكورة)، `order_items`, `order_status_history`, `delivery_offers` (عروض الإرسال للمندوبين مع مهلة وقبول/رفض)، `rejection_reasons`.
- **الموقع**: `worker_locations` (آخر إحداثيات + وقت + حالة اتصال)، `addresses` المحفوظة للزبون.
- **التقييم**: `ratings` مرتبط بطلب مكتمل، بلا تكرار لنفس الطرف.
- **الإدارة**: `audit_logs`, `notifications`, `app_settings` (مهلة قبول المندوب 1–5 دقائق، قواعد الطلبات المتعددة، التسعير والعمولات).
- **التسعير والعمولات**: `pricing_rules`, `commission_rules` مرنة حسب الخدمة/العقد/المنطقة.
- بحث ذكي: فهارس نصية (trigram) تدعم جزء الكلمة وأول الكلمة وعدة كلمات والأخطاء البسيطة عبر دالة بحث موحدة.

## الواجهات (المرحلة الأولى)
1. **تسجيل الدخول** بالبريد وكلمة المرور + استعادة، وتوجيه تلقائي حسب الدور.
2. **واجهة الزبون**: الترويسة (يمّك + الشعار)، بحث «شتحتاج اليوم؟»، الخدمات مبوّبة حسب الأقسام، قائمة المطاعم مع ترتيب (الأقرب/الأعلى تقييماً/الأكثر طلباً/المتاح الآن)، صفحة المطعم، السلة، تحديد الموقع (GPS أو يدوي على خريطة)، تأكيد الطلب، تتبع الطلب حياً، التقييم.
3. **واجهة المطعم**: استقبال الطلبات، قبول/رفض، تجهيز، جاهز للاستلام، إدارة الوجبات والأسعار.
4. **واجهة المندوب**: متاح/غير متاح، تحديث الموقع، عرض الطلب المرسل مع عدّاد المهلة، قبول/رفض مع سبب، الطلبات الحالية والسابقة، الأرباح، التقييمات.
5. **لوحة الإدارة**: إدارة الخدمات والأقسام، المستخدمون والأدوار، طلبات الانضمام والموافقات، المدن والمناطق، الطلبات، المتابعة المباشرة بالألوان (🟢🔴⚫)، التدخل اليدوي، سجل التغييرات، الإعدادات.

## محرك توزيع الطلبات
عند «جاهز للاستلام»: اختيار المندوبين المتاحين ذوي الموقع الحديث، ترتيب حسب القرب من مطعم الاستلام مع مراعاة الطلبات الحالية والاتجاه، إرسال عرض للأقرب لمدة قابلة للضبط (1–5 دقائق)، وعند الرفض أو انتهاء المهلة ينتقل تلقائياً للتالي. كل ذلك في الخلفية مع تسجيل الأسباب.

## الهوية البصرية
أحمر رئيسي أنيق مع رصاصي وأسود، خط عربي حديث، أزرار كبيرة مريحة للهاتف، انتقالات سلسة، RTL كامل.

## المراحل اللاحقة (نفس البنية)
المتاجر والمنتجات → التوصيل الخاص → طلب مندوب → التكسي → المهن والخدمات → الدفع الإلكتروني → OTP ورقم الهاتف.

## ما سأنفذه في الخطوة القادمة بعد الموافقة
تفعيل Lovable Cloud، إنشاء مخطط قاعدة البيانات كاملاً مع الصلاحيات وبيانات تجريبية أولية (مدينة، أقسام، خدمات، مطاعم، وجبات)، ثم نظام الدخول والتوجيه حسب الدور وواجهة الزبون.
